Load test 0 - WAF per-IP rate limit (bottleneck proven)
=======================================================
Date:      2026-11-22, ~12:25 BTT (UTC+6)
Target:    https://dt60dgqnqv83d.cloudfront.net  (ap-southeast-1, exam-a3 stack)
Client:    1 laptop in Phuntsholing, Bhutan = ONE public IP (simulates a class behind the campus NAT)
Tool:      k6 v2.4.0, script loadtest/exam-peak.js
Command:   k6 run -e BASE_URL=https://dt60dgqnqv83d.cloudfront.net -e STUDENTS=500 -e RAMP=1m -e HOLD=4m loadtest\exam-peak.js
Settings:  WAF_RATE_LIMIT = 2000 requests / 5 min per IP (default), API_MIN_TASKS = 2, DB = db.t4g.micro, PG_POOL_MAX = 10

Result summary
--------------
- 500 virtual students (1/6 of the 3,000 peak) from one IP
- 3,021 of 5,624 requests (53.7%) BLOCKED by WAF with HTTP 403 (waf_blocked_403 = 3021, ~7.8/s)
- Autosave success only 41% (2,103 OK / 3,021 blocked); exam load 100% OK (loads happened before the IP crossed the limit)
- Latency of successful requests: median 472 ms, p95 1.37 s (mostly Bhutan -> Singapore network round trip)

Conclusion
----------
The WAF rate-based rule (2,000 req / 5 min per IP) blocks legitimate students who share one public IP.
3,000 students autosaving every 30 s = ~30,000 requests / 5 min from the campus NAT, i.e. 15x the limit.
Fix (change C11): exempt campus egress IP ranges with an IP set (scope-down statement) or rate-limit per user
(e.g. a custom key on the Cognito user / x-user-id header) instead of per source IP.
For the capacity test the limit was raised temporarily (WAF_RATE_LIMIT = 2000000).
